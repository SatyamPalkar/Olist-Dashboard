**Profiles and exclusions** (SQL on the warehouse, re-checked in Python on the CSVs):
* **Carrier hand-off date:** it is only in `staging.stg_orders.order_delivered_carrier_date` (joined on `order_id`). Across 96,478 delivered orders:
  * 2 have no hand-off date and 8 have no customer delivery date.
  * 165 hand-offs are dated before purchase, 1,350 before approval, and 23 after customer delivery.
  * Timing therefore uses the **96,281** orders with purchase ≤ hand-off ≤ delivery; 197 are excluded.
  * Dispatch is measured from purchase because approval is not a reliable start.
  * `dispatch_days + transit_days = delivery_days` for every included order (0 mismatches above 0.02 days).
* **Multiple sellers:** 1,275 delivered orders (1.3%) have 2–5 sellers. In `order_sellers` each appears once per seller, carrying the order-level late flag, review and hand-off date, because Olist records one hand-off per order. Seller and route rates are therefore at **order × seller** grain, where the network rate is 8.02%.
* **Credit-card instalments** (payment grain):
  * 74,304 delivered orders have a card row, and 282 of them have several card rows. The order-level count is the **MAX** instalments over those rows.
  * 2 orders with 0 instalments are excluded (invalid), leaving 74,302.
  * Non-card types always have 1 instalment, except 2 boleto rows with 10; these are out of scope.
  * 2,182 card orders also used another payment type, and AOV uses the whole order value.
  * Values of 12–24 are rare but plausible, so they are kept in the 11+ band.
* **Reconciliations:**
  * Merchandise sales total R$13,221,498.11 at order, item, order × category and order × seller grain.
  * The new extracts have 0 mismatches against `orders.csv` on `is_late`, `review_score` and `delivery_days`.
  * The card extract equals an independent Python computation from `payments.csv` exactly.
* **Missing fields that limit the decision:** carrier identity, and the promised-date policy.

## 3. KPI contract

| KPI | Definition (Tableau) | Grain / eligibility | Comparator | Edge cases |
|---|---|---|---|---|
| Merchandise sales | `SUM([merchandise_sales])`; trend axis ÷1e6 | Order | Jan–Aug YoY | – |
| Late rate | `SUM([is_late]) / COUNT([is_late])` (ratio of sums) | Orders with both dates | Network `{FIXED : …}` 8.11% | Null excluded. Small cells volatile (flagged in heatmap tooltip) |
| Gap (pp) | `100 * ([Calc_Late_Rate] - MIN([Calc_Network_Late]))` | State | Network | Percentage points |
| Excess late orders | `SUM([is_late]) - COUNT([is_late]) * MIN(network)` | State / seller | Network-rate expectation | Additive; sums to 0 across all members |
| Tier | Priority: gap ≥ +3 pp and excess ≥ 50. Watch: gap ≥ +1 pp. Otherwise Monitor | 21 states with 300+ orders | – | Network ignores the 300+ filter |
| Seller dispatch / carrier transit | `AVG([dispatch_days])`, `AVG([transit_days])` | Order, `F_Valid = 1` (96,281) | Late vs on-time orders | Shared 0–38 day axis so lengths compare |
| Missed shipping limit | `AVG([missed_ship_limit])`; late rate by flag | Order (hand-off present) | Within vs after limit | Association |
| Route / seller-state late rate | `SUM([is_late]) / COUNT([is_late])` on `order_sellers` | Order × seller. Routes 500+, seller states 300+ | Network 8.02% (same grain) | Multi-seller orders counted per seller |
| Seller excess rank | SQL `rank()` of excess late orders (8.02% network) | Sellers with 100+ seller-orders (210); top 15 shown | – | Rank computed in the extract, so not filter-sensitive |
| Repeat rate by first order | `AVG([is_repeat])` | Unique customers, first delivered order before 1 Mar 2018 | Late vs on-time first order | Association. 8 customers whose first order has no late flag are excluded |
| Instalment band share / AOV | `COUNT / MIN({FIXED : COUNT})`; `AVG([order_value])` | 74,302 card orders | Across bands | Review and late rate by band are associations |

## 7. Generator notes (Tableau 2026.3 XML lessons, verified in logs and screenshots)

* **Data source form.** Write the canonical object-model form:
  * Manifest flags `ObjectModelEncapsulateLegacy`, `ObjectModelTableType`, `SchemaViewerObjectModel`, `SetMembershipControl` and `SortTagCleanup`.
  * An `<object-graph>`.
  * A layout without percentages.
  * `<computed-sort>` placed before the filters.
* **Navigation buttons** need the manifest flags `BasicButtonObject` and `BasicButtonObjectTextSupport`.
* **Colour maps.** Categorical palette maps were dropped on load for generated files, so categorical colours are numeric codes with worksheet-level `custom-interpolated` palettes and explicit `min`/`max`.
* **Container sizing.** Every flow-container child is `is-fixed` with a pixel `fixed-size`; unfixed children collapse.
* **Field derivations.**
  * Dimensions on the Tooltip shelf need `attr:`.
  * FIXED LOD calcs need an aggregate instance (`min:`).
  * Do not reuse a Python name for both a theme colour and a data source: one collision produced an invalid colour value.
* **Formats and axes.**
  * The `,,` scaling format is ignored, so use a ÷1e6 calc.
  * Date axes are fixed with an `encoding attr="space"` range.
* **Screenshots.**
  * Tableau sizes a new instance's window from `Settings.LastInstPlacement` only when no other instance is running.
  * QA copies (`--qa DIR`) are identical fixed-size workbooks that open on each page.
  * Captures were cropped to the 1440 × 840 canvas, and a capture was rejected if the log showed a `navigate-to-sheet` event.
